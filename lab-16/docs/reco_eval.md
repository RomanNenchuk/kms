# Результат 2. Офлайн-оцінка рекомендацій

Код: `reco/eval.py`, `reco/metrics.py`, `reco/plots.py`. Запуск: `make reco-eval` (≈10 с, детерміновано, seed=42). Сирі результати: `reports/eval_results.json`, таблиця `reports/eval_table.md`, графіки `reports/fig_accuracy.png`, `reports/fig_diversity.png`.

## 1. Дані й часове розбиття без витоків (C1)
- Дані: 3309 синтетичних подій, 64 користувачі, 36 документів (`data/interactions/README.md`). Релевантні події: `open`, `save`, `helpful`; `view` — не сигнал.
- **Розбиття за часом:** train = `ts < 2026-10-26`, test = `ts ≥ 2026-10-26` (до 2026-11-14). Випадкового перемішування немає.
- Усі моделі (популярність, профілі користувачів, граф історії, профіль embeddings) будуються лише з train.
- Рекомендації формуються «на момент cutoff» (`as_of = 2026-10-26`): документи, опубліковані пізніше, недоступні. Тому 4 нові документи в основній оцінці не рекомендуються (їх розглядає Результат 3).
- **Релевантні** для користувача = його позитивні події в test на документах, які система *могла* показати: пройшли фільтри (verified, свіжість, права) і не були бачені в train. Кандидати однакові для всіх конфігурацій. Користувачі без таких документів, а також «холодні» (без історії в train) в оцінку не входять.
- **Гіперпараметри** підбираються на валідаційному вікні **всередині train**: модель навчається на `ts < 2026-10-12`, оцінюється на `[2026-10-12, 2026-10-26)`. Test для підбору не використовується.

Автоперевірки витоків (`leakage_checks` у `reco/eval.py`, результат у `reports/eval_results.json`) — усі True:
| Перевірка | Результат |
|---|---|
| max ts у train < cutoff | ✓ |
| min ts у test ≥ cutoff | ✓ |
| вікно підбору параметрів закінчується не пізніше cutoff | ✓ |
| у видачі немає документів, бачених у train | ✓ |
| у видачі немає документів, опублікованих після as_of | ✓ |
| популярність і профілі враховують лише train | ✓ |

Статистика оцінюваних пар «користувач–документ» у test (позитивні події, унікальні пари): придатні для оцінки **90**; відкинуті: вже бачені в train 190, не опубліковані на момент cutoff 24, не verified 19, застарілі 17, немає прав 5, «холодні» користувачі 18. **Оцінено 47 користувачів** з 56 «теплих».

## 2. Конфігурації й метрики
Конфігурації (6, вимога ≥ 4): `Популярність` (baseline), `Граф` (α=β=γ=1), `Embeddings`, `Гібрид (за замовч.)` (RRF, ваги graph/embed/pop = 1/1/0.5), `Граф (підібр.)`, `Гібрид (підібр.)`.

Метрики (top-k, k=5 або 10; релевантність бінарна):
- precision@5 = |top5 ∩ rel| / 5; recall@5 = |top5 ∩ rel| / |rel|;
- nDCG@10 = DCG / IDCG, DCG = Σ rel_i / log2(i+1);
- coverage@5 = частка каталогу (36), що потрапила хоча б одному користувачу в top-5;
- novelty@5 = середнє −log2 p(d), p(d) = (вага подій train + 1) / (сума + 36): вище = менш популярні документи.

Підбір на валідації (nDCG@10, 43 користувачі): спочатку α,β,γ ∈ {0.5, 1, 2}³ для графа, потім метод злиття (RRF / зважена сума) і ваги embed ∈ {0, .25, .5, 1}, pop ∈ {0, .25, .5, 1} для гібрида. Обрано: α=2, β=2, γ=0.5; зважена сума з вагами graph/embed/pop = 1/**0**/0.5. Валідаційний nDCG@10 гібрида: 0.504 (за замовч.) → 0.683 (підібраний).

Різниці між конфігураціями перевірено **парним bootstrap** на тих самих користувачах (`paired` у `reports/eval_results.json`):

- embeddings значуще гірші за популярність: precision@5 −0.055 [−0.106; −0.004], nDCG@10 −0.165 [−0.269; −0.060].

## 4. Вибір кращої конфігурації (C4)
Обрано **Гібрид (підібр.)**: зважена сума, graph/embed/pop = 1/0/0.5, граф α=2, β=2, γ=0.5. Обґрунтування:
1. Критерій вибору заданий заздалегідь і застосовується на **валідації**, а не на test: найвищий nDCG@10 (0.683 проти 0.611 у графа з підібраними параметрами). Test лише підтверджує: nDCG@10 = 0.631, значуще вище за граф (+0.084) і популярність (+0.186).
2. За precision@5 і recall@5 гібрид не відрізняється від графа статистично; перевага лише в якості порядку (nDCG).
3. Coverage@5 найвищий (0.694, як у графа): 25 із 36 документів потрапляють хоч комусь у top-5.
4. **Ціна вибору:** novelty нижча, ніж у графа (5.66 проти 6.31 біт): вага популярності 0.5 повертає у видачу популярні документи. Якщо важливі «відкриття», варто взяти граф (підібр.) із нижчою pop-вагою.
5. **Embeddings отримали вагу 0** — на цих даних вони не покращують гібрид (nDCG@10 самих embeddings 0.28, нижче за популярність). Отже підібраний гібрид фактично «граф + популярність».

## 5. Обмеження оцінки
- **Синтетичні дані з тих самих сигналів, що й граф** (роль, ризики авіакомпанії): перевага графа очікувана і не доводить якість на реальних користувачах.
- **Малі вибірки:** 47 користувачів у test, 90 релевантних пар, 43 користувачі у валідації; інтервали широкі, підбір ваг на 43 користувачах може бути оптимістичним (nDCG на валідації 0.683, на test 0.631).
- **52 % позитивних подій у test — повторні відвідини документів, бачених у train** (190 із 363 пар). Політика «не рекомендувати побачене» виключає їх з релевантних; для сценарію «нагадати корисне» оцінка була б іншою.
- Бінарна релевантність (без урахування `save`/`helpful` як сильнішого сигналу) і один часовий розріз; ковзне вікно (rolling origin) не використано, бо вікно підбору параметрів перетиналося б з тестом.
- novelty і coverage залежать від малого каталогу (36 документів).
