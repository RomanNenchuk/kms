# Aviation Knowledge Hub — рекомендаційна система та демонстратор (ЛР 16)

Предметна область: управління авіаційними перевезеннями. Hub об'єднує граф знань (Neo4j), пошук по базі знань,
рекомендації з поясненнями, захищений доступ до графа й інтерфейс. Дані синтетичні (seed 42).

## Що потрібно
- Docker + Docker Compose v2 (`docker compose version`), вільні порти 7474, 7687, 8000, 8501.
- Для запуску без Docker: Python 3.12 і Neo4j (необов'язково, див. нижче).
- Ключ Gemini **необов'язковий**: без нього все працює, лише пояснення не перефразовуються.

## Запуск однією командою
```bash
cp .env.example .env          # і задай NEO4J_PASSWORD (будь-який пароль)
docker compose up --build
```
Послідовність: `neo4j` (граф) → `loader` (завантаження графа й рекомендаційних вузлів, завершується) → `api` (:8000) → `ui` (:8501).
Перший запуск ≈ 2–4 хв (збірка образу). Готово, коли в логах з'явиться `api` healthy.

| Що | Адреса |
|---|---|
| UI (Streamlit) | http://localhost:8501 |
| API (Swagger) | http://localhost:8000/docs |
| Neo4j Browser | http://localhost:7474 |

Зупинка: `docker compose down` (з `-v` — разом із даними графа).

## Перевірка, що все працює
```bash
python scripts/smoke_check.py          # 5 сценаріїв демо + права
make fresh-check                      # запуск «з нуля» в чистій теці, лог у docs/fresh_start_log.txt
```

## Змінні середовища (`.env`)
| Змінна | Призначення | За замовчуванням |
|---|---|---|
| `NEO4J_PASSWORD` | пароль Neo4j (обов'язкова) | — |
| `GEMINI_API_KEY`, `GEMINI_MODEL` | перефразування пояснень (необов'язково) | вимкнено |
| `ACCESS_LEVEL` | рівень доступу Hub за замовчуванням | `public` |
| `EMBED_BACKEND` | `bm25` (офлайн) або `e5` | `bm25` |
| `SEED` | насіння генератора даних | `42` |

## Дані для демо
- 64 користувачі (`U001–U056` з історією, `U057–U064` — холодний старт), 36 документів, 3309 подій: `data/interactions/` (генерує `make gen-data`, детерміновано).
- Граф: `data/graph/`; база знань: `data/kb/` (англійською, тому питання до бази — англійською).
- Рівні доступу: `public < internal < restricted`; користувач бачить лише доступне його рівню (pre-filter у пошуку, фільтр у рекомендаціях, мітки в Cypher).

## Розробка без Docker
```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt -r requirements-reco.txt
make test            # 105 тестів
make api             # API на :8000 (Cypher потребує Neo4j; решта працює без нього)
make ui              # UI на :8501
make reco-eval       # офлайн-оцінка (docs/reco_eval.md)
```

## Структура
`reco/` рекомендації, оцінка, пояснення, холодний старт, QA, API · `ui/` інтерфейс · `mcp_server/` Hub (пошук, граф, Cypher, guards) ·
`scripts/` генерація даних, завантаження графа, smoke-тест · `docs/` дизайн, оцінка, холодний старт, сценарій демо · `llm_log/`, `claims/` протокол LLM-експерта.

## Обмеження
Дані синтетичні й згенеровані з тих самих сигналів, що й граф, тому абсолютні метрики оптимістичні (див. `docs/reco_eval.md`).
Відповіді на питання екстрактивні (уривок документа з цитатою), не генеративні.
