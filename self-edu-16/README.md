# СР16 — оцінювання рекомендаційної системи (авіаційні перевезення)

Порівняння 3 підходів (популярнісний, контентний, граф-базований) за precision@5, nDCG@10, coverage@5, novelty@5 на даних
з ЛР 16 (синтетичні взаємодії, 64 користувачі, 36 документів, seed 42) з **часовим** розбиттям; холодний старт із числами; 4 етичні ризики із заходами.
Самодостатня: без Docker, Neo4j і мережі (embeddings e5 уже пораховані в `data/indexes/`).

## Запуск (Ubuntu, venv)
```bash
bash setup.sh                        # venv + залежності + 7 тестів
source .venv/bin/activate
bash run_all.sh                      # ≈ 15 с на CPU
```
Потрібен Python ≥ 3.10 (`sudo apt install -y python3-venv python3-pip`, якщо немає).

## Протокол (C1)
- train = події до 2026-10-26, test = 2026-10-26…2026-11-14; усе, що вчиться (популярність, профілі, IDF), бачить лише train.
- Кандидати: опубліковані до cutoff, доступні за рівнем доступу, не відкриті користувачем у train. Релевантні: `open/save/helpful` у test (`view` не рахується).
- Оцінюється 48 користувачів із ≥ 1 релевантним документом (109 пар); ті самі користувачі для всіх підходів. Інтервали — bootstrap по користувачах.
- Підходи: `pop`, `content` (TF-IDF по тексту), `graph` (роль + історія). Додатково: `embed` (e5), `random` (нижня межа), `graph_expo`.

## ⚠ Витік у графі з ЛР 16
Зв'язки «рейс—ризик» (`rel_affected_by`) мають `validFrom` 2026-11-02/03, тобто **після** cutoff, і генератор даних використав їх для уподобань.
Тому основний `graph` — без експозиції; `graph_expo` показано окремо з позначкою `*`. У звіті це варто явно написати.

## Холодний старт
`content` і `embed` без історії повертають порожній список (100 %), тому для них показано fallback на популярність.
A2 (8 реальних нових користувачів) — дуже мала вибірка, інтервали широкі; не роби з неї сильних висновків.
